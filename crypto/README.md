# NuttX Cryptographic Subsystem (`crypto`)

## Overview
OpenBSD-derived cryptographic framework (`crypto.c`), `/dev/crypto` character device (`cryptodev.c`), software cryptographic driver and key store (`cryptosoft.c`, `xform.c`), algorithm implementations (AES/Rijndael, DES/3DES, Blowfish, CAST5, ChaCha20-Poly1305, BLAKE2s, MD5, RIPEMD-160, SHA-1, SHA-224/256/384/512, GMAC, CMAC, HMAC, SipHash, AES Key Wrap, Curve25519, secp160r1/secp192r1/secp224r1/secp256r1 ECC/ECDH/ECDSA, bignum `bn.c`, Skip32 `idgen.c`), algorithm self-test manager (`testmngr.c`), and BLAKE2Xs entropy pool RNG (`random_pool.c`).

## Invariants
- `[aes.c:AES_set_key]` only accepts key sizes of 16, 24, or 32 bytes (returning `-EINVAL` otherwise); `[aes.c:aes_cypher]` requires `size % 16 == 0` and non-NULL `iv` for `AES_MODE_CBC` and `AES_MODE_CTR`.
- `[blake2s.c:blake2s_init_key]` asserts `outlen > 0 && outlen <= BLAKE2S_OUTBYTES` and `keylen > 0 && keylen <= BLAKE2S_KEYBYTES`; `[blake2s.c:blake2s]` asserts `in != NULL || inlen == 0` and `key != NULL || keylen == 0`.
- `[cryptodev.c:cryptof_ioctl]` enforces `cop->len <= 64*1024-4` (and `cop->len % blocksize == 0` when `blocksize > 1`) in `CIOCRYPT` and `caead->len <= 64*1024-4` (with `caead->len % blocksize == 0`) in `CIOCRYPTAEAD`.
- `[bn.c:bignum_from_string]` requires non-null `str`, `nbytes > 0`, and `(nbytes & 1) == 0` (even hex length) with `nbytes <= 2 * BN_ARRAY_SIZE * WORD_SIZE`.
- `[random_pool.c:blake2xs]` asserts `outlen <= 64 * BLAKE2S_OUTBYTES` and non-NULL `in`/`out` buffers.

## Side Effects
- `[crypto.c:up_cryptoinitialize]` initializes the crypto driver table (`crypto_drivers`), registers the software crypto driver via `swcr_init` (when `CONFIG_CRYPTO_SW_AES` or software cryptodev is enabled), registers `/dev/crypto` via `devcrypto_register` (when `CONFIG_CRYPTO_CRYPTODEV` is enabled), and runs self-tests via `crypto_test` (when `CONFIG_CRYPTO_ALGTEST` is enabled).
- `[cryptodev.c:devcrypto_register]` registers the `/dev/crypto` character driver; `[cryptodev.c:cryptodev_ioctl]` allocates/frees session state and temporary buffers via `kmm_zalloc`/`kmm_free` and dispatches `crypto_newsession`, `crypto_freesession`, `crypto_invoke`, and `crypto_kinvoke`.
- `[cryptosoft.c:swcr_init]` allocates the software keystore and registers software symmetric/hash/AEAD/key-management algorithms with `crypto_register` and `crypto_kregister`.
- `[random_pool.c:up_rngaddint]`, `[random_pool.c:up_rngaddentropy]`, `[random_pool.c:up_rngreseed]`, and `[random_pool.c:arc4random_buf]` mutate the global entropy pool `g_rng` under `g_rng.lock` / `spin_lock_irqsave` and mix/extract randomness via BLAKE2s/BLAKE2Xs and `getrandom`.
